# الباركود المشترك في Xzare

تم تنفيذ `@xzare/barcode` في `packages/barcode` بوحدة TypeScript مستقلة تعتمد على `@xzare/core` فقط. تستخدمها منتجات التجارة والمخزون والصيدلية والتوزيع وغيرها، دون نسخ قواعد القراءة في كل برنامج. البيانات الواردة في الاختبارات أمثلة تقنية فقط؛ لم تتم إضافة أصناف أو أسعار أو حسابات وهمية.

## ما اخترناه من المراجع المحلية

## المنفذ فعليًا

- `Barcode.parse(input, format)`: يتحقق من EAN8 وEAN13 وUPCA وGTIN14 ورقم المراجعة، أو من مجموعة محارف مقيدة للكود الداخلي CODE128. يعيد كائنًا ثابتًا يحتفظ بالنص والأصفار وحالة الحروف. CODE128 هنا سياسة **قيمة داخلية** وليس مولّد الرمز المرئي، ولا يشمل GS1-128/FNC1.
- `gs1CheckDigit(payload)`: حساب modulo-10 للأطوال 7 و11 و12 و13 قبل إضافة رقم المراجعة؛ لا ينشئ هوية GS1 عالمية عشوائية.
- `ScaleBarcodeCodec.create(profiles)`: تحقق ونسخ ثابت للإعدادات؛ حد أقصى 32 ملفًا، مع رفض البادئات المتداخلة أو المعرّفات المتكررة. لا تنفذ getters أو iterator مخصصًا للإعدادات.
- `decode`: قراءة ملصق ميزان EAN13 بعد التحقق، وإرجاع PLU بالنص و`Quantity` أو `Money` بإجمالي السعر. القيم صفر/السالبة مرفوضة.
- `encode`: تكوين قيمة ملصق من PLU كامل وكمية/إجمالي سعر موجب، مع رفض تجاوز الحقل أو التقريب الصامت. نوع القيمة يجب أن يوافق الملف؛ لا يُفهم السعر على أنه وزن. القيمة كائن بيانات عادي فيه `kind` وحقل `quantity` أو `total` فقط؛ تُرفض getters والحقول المتناقضة، دون تشغيلها.
- `KeyboardScanBuffer`: إطارات قراءة حتى 64 محرفًا، Enter/CR/LF لإنهاء القراءة، إلغاء القراءة كاملة عند overflow أو timeout أو محارف غير صالحة. يفصل بين فقدان التركيز وتكرار قراءتين حقيقيتين لنفس الصنف.

التوقيت يمنع تجميع أجزاء قراءة قديمة؛ لا يثبت أن مصدر الإدخال قارئ حقيقي. الإدخال اليدوي في نفس الحقل مسموح بنفس القواعد. مدة الخمول الافتراضية 2000ms، قابلة للضبط بين 100 و60000ms. Shift/CapsLock/NumLock لا تُضاف للكود، وBackspace للتعديل وEscape للإلغاء. إطارات Ctrl/Alt/Meta أو IME أو key-repeat مرفوضة. لا يوجد listener عام للوحة المفاتيح.

يرسل adapter كائن `ScanKeyEvent` عاديًا بحقلي `key` و`at` وأعلام boolean اختيارية. `at` توقيت monotonic مثل `performance.now()`، وليس تاريخ العميل. لا ترسل كائن DOM `KeyboardEvent` مباشرة. تقبل `push` بيانات غير موثوقة وتوقف الإطار عند شكل غير صالح؛ getters لا تُشغّل. حدود حجم رسائل IPC وتهيئة قارئ فعلي مسؤولية adapter وخدمة التطبيق.

## الاستخدام الصحيح

1. سجّل الباركود كنص للصنف **ومتغيره ووحدة بيعه**. باركود القطعة يختلف عن باركود الكرتونة؛ لا تغيّر الوحدة اعتمادًا على طول الكود وحده. يمكن للصنف امتلاك أكثر من كود مع قيد تفرد في نطاق الشركة.
2. للمنتج ذي باركود مصنع استخدم الكود الحقيقي بصيغته المسجلة. للأكواد الداخلية استخدم نطاقًا واضحًا مثل `XZ-...` عبر CODE128، مع تخصيص الهوية داخل معاملة قاعدة بيانات؛ لا تختلق GTIN عالميًا.
3. فعّل قارئ USB بوضع HID Keyboard، بلغة لوحة مفاتيح متوافقة مع الأكواد ASCII، واضبط suffix على Enter أو CR/LF. اربط الأحداث **داخل حقل المسح فقط**؛ استدع `setFocused(false)` عند blur أو فتح الدفع أو أي نافذة أخرى.
4. امنع إدخال النص الافتراضي في الحقل إذا كان `KeyboardScanBuffer` هو مالك الحالة؛ اعرض الحالة منفصلًا. لا تجمع بين إدخال DOM الطبيعي وتجميع نفس الأحداث مرتين. تجاهل paste/drop حتى يوجد مسار submit مستقل خاضع لنفس التحقق. إدخال القارئ لا يفتح روابط ولا ينفذ أوامر.
5. عند اكتمال القراءة ابحث بالمساواة التامة داخل الشركة ونطاق نوع الهوية، ثم تحقق من نشاط الصنف ووحدة البيع والسعر والمخزون. الكود غير المعروف يرجع خطأ واضحًا؛ إنشاء صنف جديد عملية منفصلة تحتاج صلاحية. لا تبحث بالاسم أو رقم قاعدة البيانات كبديل صامت.
6. نفّذ الإضافة بترتيب القراءات وبـ`scan_id`/معرّف عملية منفصل. أفرغ الحقل فور اكتمال الإطار قبل انتظار البحث؛ تكرار Enter على إطار فارغ لا يكرر الإضافة. لا تمنع قراءتين مستقلتين لنفس الكود، لأنهما قد تعنيان قطعتين.
7. حفظ الفاتورة وخصم المخزون يحتاجان صلاحيات ومعاملة واحدة و`client_txn_id`؛ `scan_id` ليس بديلًا عن حماية المعاملة. لا يسمح الباركود بإجراء خصم أو تجاوز سعر أو تجاوز مخزون.

## الميزان

**لا يوجد ملف افتراضي للبلدان.** يختار المسؤول ملفًا مطابقًا لإعداد الميزان والاتفاق المحلي. البنية الحالية:

`prefix + productDigits + valueDigits + checkDigit`

مجموع أطوال الحقول قبل رقم المراجعة = 12. حقل الوزن يدعم 0–3 منازل عشرية في الوحدة الأساسية؛ حقل إجمالي السعر يدعم منزلتين بما يطابق `Money` الحالية. الملفات التي تتضمن رقم مراجعة إضافيًا داخل حقل القيمة أو ترتيبًا مختلفًا غير مدعومة في هذا الإصدار ويجب رفضها حتى يضاف codec صريح.

مثال تقني للإعداد والقراءة، لا ينشئ صنفًا أو سعرًا تجاريًا:

```ts
import { Quantity, unwrap } from '@xzare/core'
import { ScaleBarcodeCodec } from '@xzare/barcode'

const codec = unwrap(
  ScaleBarcodeCodec.create([
    { id: 'weight', prefix: '21', productDigits: 5, valueDigits: 5, kind: 'weight', decimals: 3 },
  ]),
)
const code = unwrap(
  codec.encode('weight', '00123', {
    kind: 'weight',
    quantity: Quantity.fromMilliUnits(750),
  }),
)
const reading = unwrap(codec.decode(code))
// reading.kind === 'weight', quantity === 750 milli-units, productCode === '00123'
```

في وضع الوزن تحسب خدمة البيع الإجمالي من السعر الموثوق في الكتالوج والكمية المقروءة. في وضع السعر تعيد القراءة **إجمالي العبوة**؛ لا تتعامل معه كسعر الوحدة ولا تستنتج وزنًا بدون سياسة صريحة. يجب أن تطابق خدمة البيع العملة والوحدة والسعر وحدود المعقولية المعتمدة. ملفات الميزان محلية للشركة وليست مستنتجة من موقع الجهاز أو دولة العميل.

رقم المراجعة يكتشف بعض أخطاء القراءة؛ **ليس توقيعًا أمنيًا**، ويمكن إعادة حسابه. راجع السعر والوزن على الخادم/عملية التطبيق الموثوقة وقيّد صلاحية تعديل الملفات. أرقام التداول المحلي RCN ليست GTIN عالميًا ولا تُحوّل إلى AI (01). [دليل GS1 الرسمي](https://ref.gs1.org/guidelines/2d-in-retail/) و[حساب رقم المراجعة](https://www.gs1.org/services/how-calculate-check-digit-manually).

## الطباعة وحدود التسليم

القيمة المرمزة جاهزة لتسليمها إلى adapter طباعة، لكنها ليست صورة ملصق. سيستخدم adapter مولد رموز مرخصًا ومراجعًا، مع فصل عنوان الصنف عن الرمز، وescape للنص، ومقاس ملصق/quiet zones صحيحة، ودقة طابعة فعلية، ومعاينة قبل الطباعة. لا تستخدم محتوى الباركود كمسار ملف ولا كأمر طابعة خام.

المشروع حاليًا يحتوي النواة وهذه الوحدة، وحزمة قاعدة البيانات ما زالت scaffold. **لا توجد واجهة كاشير أو كتالوج دائم أو adapter طباعة أو اتصال مباشر بالميزان**. لم تُختبر أجهزة مادية. يلزم اختبار تشغيل لاحق: قطعة عادية، UPC بصفر أول، كرتونة، وزن، إجمالي سعر، كود تالف، صنف غير معروف، تبديل نافذة أثناء القراءة، و100 قراءة متتابعة مع مقارنة مجموع المخزون والفاتورة. لا يمكن وصف برنامج البيع بأنه جاهز تجاريًا بهذه الوحدة وحدها.
