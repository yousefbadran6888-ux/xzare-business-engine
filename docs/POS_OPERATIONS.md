# Xzare POS — دليل التشغيل والحدود

هذا الإصدار تطبيق Windows محلي للبيع والمخزون والخزينة. يبدأ بقاعدة فارغة، ويطلب إنشاء متجر وحساب مسؤول بكلمة مرور لا تقل عن 12 حرفًا. لا توجد بيانات تجارية أو حسابات أو كلمات مرور افتراضية.

## التشغيل

نسخة المراجعة الجديدة `artifacts/Xzare-POS-0.3.0-Setup.exe` لـ Windows x64. يلزم تجهيز خادم التفعيل الحقيقي وربطه وإصدار ترخيص للعميل قبل استخدام العمليات التجارية؛ النسخة الحالية لم تُربط باستضافة. المثبّت يتيح اختيار المسار وإنشاء اختصار، ويحافظ على بيانات التطبيق عند الإزالة. لم ننفذ تثبيتًا على جهاز المستخدم أو نعدّل حساباته. الإصدار غير موقّع بشهادة Windows؛ يلزم توقيع تجاري قبل توزيعه للعملاء. راجع [دليل خادم الترخيص](ONLINE_LICENSING.md) و[تحديث الواجهة](INTERFACE_REFRESH.md).

للتطوير من جذر المشروع:

```powershell
pnpm install --ignore-scripts
$env:electron_config_cache = "$PWD\.cache\electron"
node node_modules/electron/install.js
pnpm verify
pnpm start:pos
```

أوامر بديلة مستقرة: `node tools/tasks.mjs verify` و`node tools/tasks.mjs package:pos`. المعاينة عبر `pnpm dev:pos` تفتح خادمًا محليًا على `http://127.0.0.1:5191`؛ بياناتها مستقلة في `data/preview`. النسخة الموزعة تستخدم IPC ولا تفتح خادم HTTP.

## أول يوم

1. اكتب اسم المتجر والمسؤول في الخطوة الأولى، ثم اختر اسم المستخدم وكلمة المرور وأكّدها في الخطوة الثانية. اكتب الهاتف والعنوان وتذييل الفاتورة من الإعدادات.
2. فعّل ترخيص الجهاز عبر الإنترنت من الإعدادات بعد تجهيز الخادم، ثم أضف أصنافك الفعلية وأكوادها ووحداتها وأسعارها. المخزون لا يتغير عند تعديل الصنف.
3. سجّل الكمية الافتتاحية وتكلفتها بحركة مخزون مع سبب، أو سجّل فاتورة شراء.
4. افتح وردية بالنقدية الفعلية. استخدم قارئ USB بوضع keyboard wedge وإنهاء القراءة بـ Enter، داخل حقل مسح الباركود.
5. اختر العميل للبيع الآجل، وسجّل المدفوع نقدًا أو بطاقة أو تحويلًا. هذه وسائل **تسجيل دفع تم فعليًا**؛ التطبيق لا يعالج بطاقات مصرفية أو يستدعي بوابة دفع.
6. يمكن تعليق الفاتورة واستئنافها. لا يتغير المخزون إلا بعد الحفظ النهائي.
7. الدفعات الجزئية والمرتجعات تتم من الفاتورة الأصلية. المرتجع يحتاج مديرًا ويعيد تكلفة الصنف المحفوظة؛ يدعم إرجاع البضاعة التي كانت قيمتها صفرًا.
8. سجّل المصروفات والإيداع والسحب، ثم عدّ النقدية وأغلق الوردية. يُرفض السحب الذي يتجاوز الرصيد المتوقع.

الصلاحيات: المسؤول يدير الإعدادات والحسابات والنسخ والترخيص؛ المدير يدير الأصناف والمخزون والمشتريات والمرتجعات والتقارير؛ الكاشير يبيع ويدير العملاء وورديته. تكلفة المخزون لا تظهر للكاشير، ولا يستطيع تغيير الضريبة الافتراضية أو منح خصم.

## الباركود والميزان والطباعة

CODE128 وEAN-8 وEAN-13 وUPC-A وGTIN-14 مع التحقق من الصيغة ورقم المراجعة. لا تمنح عملية التوليد ملكية رقم GS1؛ استخدم أكواد شركتك المصرح بها أو CODE128 الداخلي.
في نموذج الصنف اضغط «مسح باركود الصنف»، ثم امسح بالقارئ. Enter يفحص الرمز دون حفظ الصنف، ويحفظ الأصفار في بدايته. اختر الصيغة التجارية المناسبة؛ يرفض الحفظ رقم المراجعة غير الصحيح والتكرار. عند وجوده يمكنك فتح الصنف المسجل بدل إنشاء نسخة منه. أكمل الاسم والوحدة والسعر الفعليين؛ لا يجلب التطبيق بيانات تجارية وهمية من الباركود.

ملف الميزان متوقف افتراضيًا. اضبط بادئة الجهاز وعدد خانات PLU وعدد خانات الوزن ومنازله العشرية من الإعدادات. مجموع البادئة وخانات الصنف والوزن = 12، ثم خانة المراجعة. سجّل PLU نفسه، بما فيه الأصفار، كـ CODE128 للصنف. الإصدار يقرأ **الوزن**؛ ملفات إجمالي السعر لا تتحول تلقائيًا إلى كمية.

زر الفاتورة يفتح طباعة Windows أو حفظ PDF. اختر ورق 80mm في تعريف الطابعة؛ مساحة الإيصال 72mm. ملصقات الباركود تُرسم على Canvas ثم تطبع، مع مسافات بيضاء حول الرمز. توليد الملصق اختُبر بصريًا، لكن الطابعة والقارئ والميزان الفعليين لم يختبروا. لا يوجد إرسال ESC/POS مباشر أو تنسيق فاتورة A4 متخصص في هذا الإصدار.

## البيانات والنسخ والاستعادة

النسخة المثبتة تحفظ قاعدة SQLite في مجلد `app.getPath('userData')`، افتراضيًا `%APPDATA%/xzare-pos`. الخادم التجريبي لا يستخدم هذا المجلد. لا تنقل قاعدة مفتوحة يدويًا؛ استخدم زر النسخة الاحتياطية.

تؤخذ لقطة SQLite متسقة مع manifest وبصمة SHA-256 في `.xzbak`. نسخة تلقائية عند التشغيل إذا كان المتجر مهيأ، ثم فحص كل ساعة لإنشاء نسخة اليوم، والاحتفاظ بآخر 7 أيام. النسخة المحلية لا تعوّض النسخة الخارجية.

النسخة **غير مشفرة**؛ البصمة تكشف التلف ولا تثبت أن صاحب الملف موثوق. احتفظ بالملف على وسيط محمي. الاستعادة تتطلب مسؤولًا وكلمة مروره وإغلاق جميع الورديات، وتتحقق من الهوية والمخطط والسجلات الأجنبية وسلامة SQLite قبل الاستبدال. تُنشأ نسخة `before-restore-*.xzbak` وقاعدة سابقة داخل مجلد البيانات. عند فشل خطوة الاستبدال يعاد فتح القاعدة الأصلية. الحسابات تأتي من النسخة المستعادة وتُلغى جميع جلساتها؛ ترخيص الجهاز الحالي وإعدادات التجربة والساعة تبقى محفوظة.

## الترخيص

نسخة Windows 0.2 تتطلب تفعيلًا عبر الإنترنت؛ لا توجد تجربة محلية قابلة لإعادة التصفير. يربط الخادم كل شراء بهوية جهاز واحدة، ويصدر تصريح Ed25519 موقّعًا لمدة تصل إلى ٧ أيام للعمل دون اتصال. يلزم تجديد الاتصال بعد إعادة تشغيل Windows؛ عند تعذر قراءة هوية تشغيل Windows يلزم التجديد بعد كل فتح للبرنامج. المعاينة المحلية للتطوير تحتفظ بسياسة 0.1 ولا تمثل الترخيص التجاري.

مفتاح المُصدر الخاص لا يدخل المثبّت أو Git. احتفظ بنسخة محمية منه على جهاز المُصدر/الخادم. كود التفعيل مخفي في الواجهة ويُمسح عند الإرسال؛ مفتاح الجهاز وتصريح التشغيل محميان بـ Windows DPAPI خارج قاعدة النشاط والنسخ الاحتياطية. انقطاع الاتصال لا يمدد المهلة. يمكن إيقاف الشراء من الخادم؛ الجهاز غير المتصل قد يحتفظ بمهلته المتبقية. تنفيذ التشغيل والإصدار والإيقاف موضح في [ONLINE_LICENSING.md](ONLINE_LICENSING.md).

```powershell
node tools/license-server.mjs issue PRIVATE_CONFIG_JSON "اسم العميل الحقيقي" PRIVATE_NEW_PURCHASE_JSON
```

هذه مسارات إعدادات وتسليم خاصة يحددها المُصدر الحقيقي. أدخل قيمة `code` من ملف الشراء في الحقل المخفي، وليس ملف JSON كاملًا. تراخيص 0.1 تحتاج إعادة إصدار ولا تعمل في النظام الجديد. لا تنقل نسخة عميل عاملة قبل تجهيز الخادم وترخيصها. لا توجد مزامنة متعددة الأجهزة أو خدمة تفعيل منشورة حتى الآن.

## حدود الإصدار ودليل التحقق

EGP فقط، مخزن واحد، وحدة أساسية واحدة لكل صنف، 3 منازل عشرية للكمية، تكلفة متوسط متحرك بالقيمة الإجمالية. المشتريات تشمل ضريبتها وخصمها ضمن تكلفة الاقتناء؛ لا يوجد دفتر VAT مستقل أو فاتورة إلكترونية معتمدة. التقارير تشغيلية وليست قوائم محاسبية قانونية.

الواجهة تعرض حتى 10,000 صنف و2,000 فاتورة حديثة و500 حركة؛ تصدير الفواتير من هذه القائمة نفسها. التقارير الزمنية تجمع من كامل القاعدة. لم ننفذ benchmark لـ100,000 صنف/مليون سطر. التقارير الحالية إجماليات بيع/مرتجعات/تكلفة/مصروفات وقيمة المخزون والأرصدة والورديات، وليست جميع تقارير خارطة المنتجات الثلاثين. تغيير الاتجاه واللغة يعمل؛ بعض نصوص العمليات تظل بالعربية.

319 اختبارًا في 23 ملفًا مع typecheck/build. اختبارات HTTP فعلية للخادم تحققت من ربط جهاز واحد ومنع إعادة الطلب وحدود كل مصدر واستمرار المهلة عند الأعطال وفشل تسليم كود الشراء دون حفظ شراء يتيم. تدفق UI تحقق من الباركود والأصفار وفتح الصنف الموجود والبيع والمخزون والمرتجعات والنسخ والورديات. في 0.3 اختُبر التسجيل على خطوتين وتأكيد كلمة المرور ومسحها بعد رفض الدخول والاختصارات وتركيز النوافذ والقائمة الصغيرة والدخول والكاشير على أحجام مختلفة. إخفاء حقل التفعيل ومسحه عند الرفض، والحفاظ على التركيز عند رفض حفظ صنف، اختُبرا ببديل نقل داخل اختبار الواجهة فقط؛ لا يمثل خدمة منشورة. مشكلات المراجعة المستقلة عولجت واختبرت.
