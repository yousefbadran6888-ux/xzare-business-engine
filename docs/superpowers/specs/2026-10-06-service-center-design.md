# Xzare Service Center 0.1.0 design
Product7, standalone Arabic/EGP Windows app for device repair centers. User has authorized portfolio and sequential implementation; execute inline. Shared Identity/Inventory/Backup/License composition, independent service-center schema/applicationID, data path and product license.

## Device intake and lifecycle
Device registry: owner/contact, device type, brand/model, mandatory unique normalized serial (center can enter its own physical asset tag when manufacturer's serial unavailable). Serial immutable once any job exists; owner/catalog edits do not change frozen job device facts. Technicians active registry. Intake freezes device, complaint, external condition, accessories, due date and source warehouse. One open job per device. No collection of device unlock/password secrets.
Immutable diagnosis/estimate revisions with barcode parts and services, bounded cents/milli quantities and BigInt rounding. Customer approval must match latest displayed estimate id and assign active technician. Start atomically consumes available nonexpired FEFO lots, full serial units only, preserving immutable actual cost. Ready requires repair and inspection notes plus actual labor cost. Partial cash/bank/card payments only ready; overpayment blocked. Handover requires full payment and reference. Cancellation only before stock consumed. Payload/actor-bound idempotency and audit on every write. Manager/admin write, clerk view only.

## Warranty
Paid repair estimate sets explicit warrantyDays (0-365) and warrantyTerms; positive days requires terms. Terms freeze on approval. Delivery starts warranty at deliveredAt, bounded to exact UTC elapsed days. Within valid window manager can create linked warranty intake on same device from an original delivered paid/regular job with positive warranty. Reference original job, record new complaint/condition/accessories and acceptance reason. Only one open job per device. Warranty is zero-charge (all line prices/discount/tax zero), but parts and labor retain actual internal cost; no payment on zero total. Warranty returns do not restart or extend original warranty. No chaining warranty from a warranty return, no automatic assumption about defect coverage: manager explicitly records accepted coverage. Original history remains immutable. After expiry refuse covered return; ordinary paid intake still available.

## UI
Distinct device receipt queue and search by serial, customer or receipt; registered devices/history, technician registry, linked warranty return with expiry/terms shown in job detail. Own icon and blue-violet service identity; neutral stock/barcode panels and users/audit/license/backup shared. Printable receipt includes serial/condition/accessories/customer, quote revision, totals/payment and warranty terms. Date-filtered complete-history CSV reports separate revenue, parts/labor cost and covered warranty cost. Empty startup/no fake business rows. No vehicle/odometer UI.

## Bounds and delivery
Single company Arabic/EGP. No deposits/refunds/data recovery/remote device access/electronic tax integration. Full automated tests and UI actual stock/payment/warranty workflow in isolated QA database. Production package/native launch/fuses/source/secret audit; full named D directory with installer, win-unpacked, blockmap, SHA256 and Arabic docs. Review build until production HTTPS activation host and publisher signing configured. No zero-risk security claim.
